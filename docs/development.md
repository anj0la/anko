# Development Notes

## Why I Built This

I initially came up with the idea because I wanted a tool that would let me create issues directly from comments in my code. I found that I was already making these kinds of comments in my other projects, so I figured this was something I could build in a couple of days if I kept the first version small.

I also wanted to use the project as an opportunity to gain experience with things I hadn't worked with much before, particularly Rust, GitHub App authentication, and GCP/Firestore.

## AI-Assisted Development

I used this project as an experiment in AI-assisted development. I intentionally used AI more heavily than I normally do to get some real experience incorporating it into my development workflow.

I used AI to help scope the project down to something I could realistically finish in a few days. I wrote most of the implementation myself in Rust, though I did use AI to make some of my code less verbose and rough. 

I also used AI to explain unfamiliar concepts, such as GitHub App authentication, GCP/Firestore setup, and Rust idioms. When I had code that wasn't working or that I knew was poorly written, I used AI to help identify the problem and improve it.

This is somewhat different from how I normally use AI in my other projects. Usually, I use it more as a sounding board for ideas or as a debugging tool while writing the implementation myself. With this project, I intentionally experimented with a more involved AI-assisted workflow.

The goal wasn't to have AI build the project for me. I wanted to understand what using AI as part of a development workflow actually looked like, where it was useful, and where I still needed to make the decisions and understand the code myself.
